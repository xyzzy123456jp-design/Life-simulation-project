このドキュメントは、Jenniferのうなずき動作を実装するための仕様。まばたき(FACIAL_EXPRESSION_SPEC参照)と異なり、Morph Targetではなくボーン回転で実現するため、事前にリグ構造の変更が必要になる。

## ステップ0(実装前に必ず読むこと): 事前調査で確認済みの事実

**この内容はCodexによる調査で既に確定している。以下を前提として設計する。**

- MetaHuman本体(`BP_Payton`)には標準の`neck_01 → neck_02 → head`というボーン階層が存在する
- Body側は`ABP_MetaHuman_f_med_nrw_Retargeting`で制御されている
- Face側には`Face_AnimBP`と`Face_PostProcess_AnimBP`があり、Post Process内の`HeadMovementIK_Proc_CtrlRig`が`neck_01`/`neck_02`/`head`を扱っている
- C++には現状、Head/Neck Boneを直接書き換える処理は存在しない(カメラ方向を向く処理はあるが、これは`CharacterActor`全体のYaw回転であり、頭部単体の回転ではない)
- **実際に画面へ表示されているCrimsonメッシュには`root`ボーンしか存在しない。全389,619頂点が`root`へ100%ウェイトされている**
- CrimsonはMetaHuman本体のLeader Poseへ接続されていない
- MetaHuman側の`head`ボーンを動かしても、Crimson側は一切追従しない
- Crimsonの`root`を直接回転させると、頭だけでなく肩・胴体を含むメッシュ全体が回転してしまう

**結論**: 現状のまま、C++からMetaHuman側の`head`ボーンへ回転を追加する方式は採用できない(既存の`HeadMovementIK_Proc_CtrlRig`に上書きされる上、表示中のCrimsonには反映されない)。うなずきを実装するには、**先にCrimson側へhead/neck相当のボーンを追加し、頭部・顔・髪と肩・胴体のウェイトを分離するリギング作業が必要**。

## 1. 全体方針: 2フェーズに分ける

- **フェーズA: Crimson簡易Head Rig化**(本仕様の主眼。Blenderでのリギング作業)
- **フェーズB: 単発うなずきの実装**(AI連動なし。「下へ5〜8度 → 元へ戻る」1回だけの動作をDeltaTimeベースで実装)
- **フェーズC: Function Calling連動**(本仕様のスコープ外。フェーズBの動作確認後、別工程として改めて仕様化する)

今回は**フェーズAとフェーズBのみ**を対象とする。フェーズCは着手しない。

## 2. フェーズA: Crimson簡易Head Rig化

### 2.1 目的

Crimsonメッシュへ、頭部だけを独立して回転させられる最小限のボーン構造を追加する。MetaHuman本体と同じ精巧なリグを再現する必要はなく、うなずき動作に必要な最小限の構成でよい。

### 2.2 実装前に確認すること(【必須】)

1. **既存のMorph Target(表情18種 + `jawOpen`/`mouthSeal` + `eyeBlinkLeft`/`eyeBlinkRight`)が、ボーン追加・リウェイト後も正しく機能するか**を確認する。Shape Key(Morph Target)は基本的に頂点インデックスに紐づいており、スキニング(ボーンウェイト)とは独立した仕組みのはずだが、Blenderでのリグ変更・再エクスポート作業によって頂点順序が変わらないことを必ず確認する。頂点順序が変わると、既存の全Morph Targetが壊れる重大な事故になる
2. ボーン名を、MetaHuman標準に合わせる(`neck_01`、`neck_02`、`head`)か、Crimson専用の別名にするかを検討する。将来的にMetaHuman本体側の仕組み(Leader Pose等)と接続する可能性を考えるなら、標準名に揃えておいた方が拡張しやすい。**ただし、標準名を使用することで将来の接続可能性は高められるが、同名BoneにしただけでMetaHuman Leader Poseとの互換性が成立すると仮定しないこと。**Skeleton階層・Reference Pose・Bone Transform等の互換性は別途必要であり、今回はLeader Pose接続そのものを実装しない
3. ウェイト分離の境界線をどこに置くか(首のどの高さで頭部側と胴体側を切り分けるか)を、実際のメッシュを見ながら決める
4. **ボーンの階層・親子関係・pivot(回転中心)・向き(Bone orientation)を明確に決める。** 基本候補は`root → neck_01 → neck_02 → head`という階層とする。各Boneのpivotは実際の関節位置に合わせること。`neck_01`/`neck_02`は首の下部〜上部、`head`は頭部と上頸部の接続位置を基本候補とする。最終位置はBlender上で実際に5〜8度Pitchさせてみて、自然な首の変形になる位置を採用すること。**pivotを「首の付け根」のような単一の固定位置に決め打ちしないこと**(headのpivotだけを首の付け根に置くと、本来`neck_01`/`neck_02`が担うべき可動域をheadが肩代わりすることになり、3段階の階層を作る意味が薄れる)。ここを誤ると、うなずきが「首から自然に傾く」動きにならず、「頭部全体が空中で回転・平行移動するような」不自然な見た目になる
5. **Bone追加・ウェイト変更の過程で、Crimsonメッシュの既存Reference Pose(頂点の基準位置・向き・スケール)を変更しないこと。** Bone追加前後で、ニュートラル状態(nod・表情・まばたきいずれも適用していない状態)の外観が完全に一致することを確認する。これを怠ると「うなずいていないのに首や顔の位置が微妙にズレた」という気づきにくい回帰事故につながる

### 2.3 作業内容

1. Blenderで、既存のCrimsonメッシュ(表情Morph・まばたきMorphを含む最新版)に対し、`neck_01`/`neck_02`/`head`(またはそれに準ずる)ボーンを追加する
2. 頭部・顔・髪の頂点を`head`(または該当ボーン)へ、肩・胴体の頂点を`root`へウェイトペイントする。首の境界付近は急激な折れ目が出ないよう、`head`と`root`の境界部分だけ滑らかなグラデーション(両ボーンにまたがる部分的なウェイト)を持たせる

**頂点ウェイト分けの範囲について**: 今回のうなずきは5〜8度程度の小さな動きであるため、首全体を複数箇所でなだらかに曲げる必要はなく、頭部側の頂点を基本的には`head`1箇所へまとめてウェイトする単純な分け方(境界付近のグラデーションを除けば実質2値の分離: `head`か`root`か)で十分とする。`neck_01`/`neck_02`は主に回転を伝えるための中継ボーンとして扱ってよく、これらに頂点ウェイトを個別に割り当てる作業は必須ではない。Blender上で実際に回転させてみて、この単純な分け方のままで不自然な折れ目が出ないことを確認できれば、それで良しとする。もし不自然さが出る場合のみ、首の頂点を`neck_01`/`neck_02`/`head`へ段階的に分散する対応を検討する。

3. 全既存Morph Targetが変形前と変わらず機能することを、Blender上で1つずつ確認する。表情18種、`jawOpen`、`mouthSeal`、`eyeBlinkLeft`、`eyeBlinkRight`をすべて個別に確認すること
4. FBXへエクスポートする。**既存の正常なCrimsonへいきなり上書き再インポートしないこと。** まずテスト用の別Skeletal Mesh/Skeletonアセットとして一時的にUEへインポートし、Bone階層・Morph Target・ウェイト・マテリアルが正常であることを確認する。そこで問題が無いと確認できてから、初めて既存Crimsonアセットを更新する。既存アセットを最初から不可逆に上書きしないこと

### 2.4 合格条件(フェーズA)

1. UE上で`head`(または該当ボーン)を手動で回転させると、頭部・顔・髪だけが動き、肩・胴体は動かない
2. **既存の全Morph Target(表情18種、`jawOpen`、`mouthSeal`、`eyeBlinkLeft`、`eyeBlinkRight`)が、リグ変更前と同様に正常動作すること**(Eキー・`TestFaceCurve`等の既存診断コマンドで確認。表情・まばたきだけでなく、口パクも必ず確認する)
3. 首の境界に不自然な破れ・折れ目が出ない
4. `head`を5〜8度Pitch回転した際、**首から自然に傾いたように見える回転になり、頭部が平行移動したように見えないこと**(2.2のBone pivot確認と対応。`neck_01`/`neck_02`/`head`それぞれの関節位置・pivotが適切であることの結果として確認する)
5. **`head`を5〜8度Pitchさせた状態でも、表情Morph、`jawOpen`、`eyeBlinkLeft`/`eyeBlinkRight`を同時適用して正常に変形すること。** Bone変形とMorph変形を単体でそれぞれ確認するだけでなく、**同時に適用した場合**に顔・首・口・まぶたに破綻が出ないことを確認する(例: `head`を傾けた状態でhappy表情+まばたきの瞬間+口パクが同時に起きるケースを想定した確認)
6. **Bone追加・ウェイト変更後も、ニュートラル状態(nod・表情・まばたき非適用時)の外観がリグ変更前と一致すること(Reference Poseが変化していないこと)**

## 3. フェーズB: 単発うなずきの実装

**フェーズAの合格条件をすべて満たしてから着手すること。**

### 3.1 実装前に確認すること(【必須】)

1. **うなずき更新処理をどのクラス・どのTickへ追加するのが既存構造上自然かを確認する。** まばたきはMorph Target操作だったため`LipSyncComponent::TickBlink()`が自然な置き場所だったが、うなずきはボーン回転という別種の操作である。`LipSyncComponent`(Morph制御が主目的)にそのまま追加してよいか、あるいは`RealtimeTestActor`側や別の専用コンポーネントに置く方が既存構造上自然かを、コードを確認した上で判断する。新しいActor Tickを不必要に増やさないことを優先しつつ、既存のクラス責務を歪めない置き場所を選ぶこと
2. Crimson側に追加した`head`ボーンへC++から回転を加える際、`Component Space`と`Local Space`のどちらで加算すべきかを、実際にUE上で試して確認する(親ボーンの現在の回転によって結果が変わるため、コードだけでは判断できない)
3. MetaHuman本体側の`HeadMovementIK_Proc_CtrlRig`は、あくまでMetaHuman本体の`head`ボーンを制御するものであり、Crimson側の新設ボーンとは無関係である。**Crimson側の`head`ボーンに対して、他にこの値を書き込んでいる処理がないか**を確認する(所有権の競合防止。以前の`jawOpen`所有権と同じ考え方)
4. `TestNod`(またはそれに準ずる新規テストコマンド)を追加する際、**既存のキー割り当て(`InputComponent->BindKey`)を確認し、Eキー・Rキー等の既存コマンドと衝突しない空いているキーを選ぶこと**
5. **Crimsonの`head`回転を最終的にどのUE機構で適用するかを実装前に確認すること。単にC++ TickからBone Transformを書けば維持されると仮定しないこと。** Skeletal MeshにAnimation Blueprintが設定されている場合、C++から直接Boneへ値を書いても、その後のAnimGraph評価(候補: `Transform (Modify) Bone`ノード、Control Rig、専用AnimInstance等)で上書きされてしまう可能性がある。これは所有権競合(3.1項目3)とは別の問題で、「値を書く権利を持っているか」ではなく「書いた値が評価順序の後段で上書きされずに最終的な描画へ反映されるか」の確認である。実際に既存のBone回転処理(または類似の仕組み)がAnimBP/Control Rig/Post Process等のどの段階でどう評価されているかを確認し、毎フレーム別処理に上書きされない経路を選ぶこと

### 3.2 動作仕様

- AI連動なし。まずは手動テストコマンド(Eキー/Rキーに相当する新しいテストコマンド、例: `TestNod`)で単発発火できるようにする
- 回転量: 頭を下へ**5〜8度**傾け、元の角度へ戻る
- 1回のトリガーにつき1回のうなずき(まばたきのような自動ループ・ランダム間隔は今回不要)
- `DeltaTime`ベースで滑らかに補間する(まばたきの`Closing`/`Closed`/`Opening`と同様の考え方。「下げる」→「(必要なら短い保持)」→「戻す」の3段階程度を想定)。コード上のフェーズ名は、まばたき用語(`Closing`/`Closed`/`Opening`)をそのまま流用せず、`NodDown`/`Hold`/`Return`のようなうなずき向けの名前にすると可読性が良い(必須ではなく推奨)
- 具体的な各段階の時間は、実装時にUE上で見ながら自然に感じる値へ調整してよい(まばたきのように厳密な秒数を事前に固定する必要はない)
- **Nodは既存のBase Poseを上書きせず、その時点の頭部姿勢へPitch差分を加算(additive rotation)として扱う。終了時はnod開始前の基準姿勢へ自然に復帰すること。絶対Rotation値の固定書き込みは禁止する。**(理由: 将来Idle Animation等で頭部が常に動いている状態が追加された場合、絶対値を書き込む実装だと、その時点の元姿勢を破壊してしまうため。例えば元のhead回転が12度だった場合に、nod開始で絶対値`-6度`を設定してしまうと、終了時に元の12度へ戻らず0度になる、といった事故を防ぐ)
- **うなずきが進行中(`NodDown`/`Hold`/`Return`等)に、再度`TestNod`が実行された場合の挙動を明確にすること。** まばたきは自動ループで「待機中のみ新しいまばたきを開始する」設計だったため衝突しなかったが、うなずきは手動トリガー式のため、進行中の再トリガーを無視するか、現在の動作を打ち切って最初からやり直すか、次のうなずきをキューに積むかのいずれかを選び、実装コメントに理由とともに明記すること。いずれの方式でも、Base Poseへの復帰(上記のadditive rotationルール)を壊さないこと

### 3.3 変更禁止

以下は今回変更しないこと。

- 既存の表情制御(Realtime/Legacy双方のexpress_emotion、Direct Morph)
- 自動まばたき(`TickBlink`)
- 口パク(`jawOpen`)
- Legacy録音/VAD(`VoiceActivityThreshold = 0.05`、無音1.8秒、最大録音20秒)
- Legacy STT(`gpt-4o-mini-transcribe`)
- Legacy感情TTS(`gpt-4o-mini-tts`、TTS instructions)
- Realtime API側の音声処理
- Eキー/Rキー(既存の診断コマンド)

### 3.4 合格条件(フェーズB)

1. `TestNod`(または同等の新設テストコマンド)を実行すると、頭部だけが下へ5〜8度傾き、自然に元へ戻る
2. 動作中、既存の表情・まばたきが継続して正しく動く(うなずき中に表情が消えたり、まばたきが止まったりしない)
3. 動作が`DeltaTime`ベースで、フレームレートによって速度が変わらない
4. 既存の口パク・録音・STT・TTS・Realtime処理に影響がない
5. うなずき進行中に`TestNod`を再度実行しても、仕様通りの挙動(無視/やり直し/キュー等)になり、頭部の姿勢が破綻しない
6. **`TestNod`を10回程度連続実行しても、Nod終了後に追加したnod offsetが毎回確実に0へ戻り、頭部の基準姿勢(Base Pose)が回転誤差の蓄積によって徐々にズレていかないこと**(`DeltaTime`補間+additive処理では、実装次第で小さな回転誤差が積み上がる事故があり得るため)
7. ビルド成功

## 4. 今回のスコープ外(フェーズC、将来の課題)

- AIが会話の同意・肯定のタイミングで自発的にうなずく(Function Calling連動、例: `nod_head`のような新規ツール定義)
- うなずきの強度・速度のバリエーション
- 複数回のうなずき、首振り(横方向)等の派生動作

これらはフェーズBの動作確認が完了してから、別途仕様化して検討する。

## 5. 実装順序

1. ステップ0の確認済み事実を前提として理解する(再調査は不要)
2. フェーズAの実装前確認事項(2.2)を実施する。特にMorph Targetがリグ変更後も壊れないことの確認は最優先
3. フェーズAの作業(2.3)を行い、合格条件(2.4)を満たすまで繰り返す
4. フェーズBの実装前確認事項(3.1)を実施する
5. フェーズBの動作仕様(3.2)に従い、`TestNod`等の手動テストコマンドで実装する
6. 合格条件(3.4)を確認する
7. フェーズCは着手せず、必要になった時点で別途仕様化する
